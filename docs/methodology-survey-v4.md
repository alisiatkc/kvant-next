# Индивидуальная анкета по гипотезе: версия 4.0

## Содержание и место в исследовании

Анкета находится на `/survey/`. Из раздела «T0–T3» кабинета доступны отдельные ссылки на входную и итоговую формы. В разделе исследований куратора добавлены результаты v4, выгрузка ответов и кодировочная книга CSV. Прежняя исследовательская форма T0–T3 продолжает работать отдельно. Записи прежней `/survey` версии 3.0 в `methodologySurveyResponses` не изменяются и не включаются в результаты v4.

T0 проводится при формировании проекта до начала использования новой среды. Вопросы об уже совершённых действиях относятся к последнему завершённому проекту; при отсутствии опыта они скрываются. T1 фиксирует фактическую активность, содержательные обсуждения внутри и между командами, обмен опытом, получение и использование рекомендаций. В10.1–В10.6 и И11.1–И11.6 имеют одинаковые формулировки и шкалу: это парные показатели готовности и значимости. Фактическая активность в T1 не сравнивается с нулевой активностью до начала проекта.

Анкета сама по себе не доказывает причинное влияние среды. Для проверки гипотезы нужны наблюдение, цифровые следы и анализ доработок проектных продуктов. Состав выборки, сроки, сопутствующие изменения условий и правила обработки повторных отправок фиксируются в протоколе апробации. Инструмент авторский, не является валидированной психометрической шкалой. Ориентировочное время заполнения уточняется после пилотирования.

Все содержательные вопросы допускают пропуск. Согласие обязательно. 0, пропуск, NP (пока неприменимо), ZO (затруднение), NI (не использовал функцию) различаются. Индивидуальный случайный код из 6 латинских букв/цифр не совпадает с командным логином; для сопоставления T0/T1 используется тот же код. В T1 код можно не вводить при утрате: запись сохраняется без парного сопоставления. Не вводить имена или контактные данные в свободных полях.

## Режимы

- `NEXT_PUBLIC_DEMO_MODE=true`, без API: данные и черновики только в браузере. Запись в браузере не означает передачу исследователю. Куратор видит только локальные записи своего браузера.
- `NEXT_PUBLIC_API_URL` задан: отправка в серверное хранилище. При ошибке сети локальная запись не выдаётся за успешную серверную отправку, черновик остаётся доступен для повтора.
- Нет API и демонстрационный режим выключен: отправка недоступна.

Черновики T0 и T1 раздельные (`kvant_methodology_v4_draft_T0/T1`), содержат личный код. После успешного сохранения текущий черновик удаляется. На общем устройстве нужно очистить данные сайта. Локальные демонстрационные ответы хранятся в `kvant_methodology_v4_responses` с SHA-256-псевдонимом; это демонстрационный идентификатор, не защита от перебора. Сервер использует HMAC с секретом.

## Подключение центрального сбора

1. Создать отдельную Document API таблицу `methodology_surveys` с первичным ключом `id` (строка) в той же базе, которую использует функция. Выдать сервисному аккаунту функции права чтения/записи. Не добавлять таблицу к публичным выгрузкам.
2. Развернуть обновлённую `cloud-function` целиком, включая `methodology-survey.js` и `methodology-survey.json`, с зависимостями из её `package.json`. Обработчик остаётся `index.handler`.
3. Установить `METHODOLOGY_SECRET` (случайный секрет не менее 32 символов), хранить только на сервере; не менять в ходе исследования, иначе сопоставление кодов изменится. При отсутствии используется существующий `SESSION_SECRET`. Не публиковать секрет в GitHub, JavaScript или CSV. Опционально `METHODOLOGY_TABLE` задаёт другое имя таблицы. Существующие настройки Document API, аккаунтов и сессий сохраняются.
4. Установить `ALLOWED_ORIGIN=https://alisiatkc.github.io`. На стороне облака настроить допустимый объём запросов и ограничения частоты публичного endpoint: индивидуальная отправка не требует командной авторизации. Не собирать тела запросов и коды в журналы.
5. Указать в GitHub Repository Variables `NEXT_PUBLIC_API_URL` — публичный адрес развёрнутой функции. Workflow передаст URL в сборку и отключит демонстрационный режим. Пересобрать/опубликовать Pages.
6. Выполнить пробную отправку T0 и T1 с одним тестовым кодом на разных устройствах. Войти как куратор: проверить обе записи, совпадение `participantId`, выгрузку CSV и запрет выгрузки без авторизации. Исключить тестовые данные из исследования до набора участников. Только после этой проверки приглашать респондентов.

API: `POST ?action=submitHypothesisSurvey` с `{survey: {instrumentVersion:'4.0', stage:'T0'|'T1', participantCode, consentConfirmed:true, submissionId:UUID, answers:{...}}}`. `GET ?action=getHypothesisSurveys` требует Bearer-сессию куратора и читает все страницы таблицы. Исходный код участника и командный аккаунт не сохраняются. `participantId` = HMAC-SHA256 от нормализованного кода с доменным префиксом v4; без кода — уникальная непарная запись. Серверные дата и идентификатор включены в выгрузку.

Каждое новое заполнение получает UUID. Повтор сетевой отправки того же UUID идемпотентен; изменить уже сохранённую запись этим UUID нельзя. Новые отправки одного участника не перезаписывают старые: панель отмечает число кодов с повторами. Перед анализом выбрать одну запись каждого этапа по заранее принятому правилу (например, последнюю допустимую запись до установленного срока), сохранив исходную выгрузку. Автоматического суммарного «балла активности» нет.

CSV в UTF-8 с BOM, разделитель `;`. Пустые ответы пусты, множественные — JSON-массивы. Формулы в свободном тексте экранируются для безопасного открытия в табличном редакторе. Кодировочная книга содержит идентификаторы, формулировки, варианты ответов, парные вопросы и показатели. Для полных условий переходов см. каноническую схему `cloud-function/methodology-survey.json`.

## Проверка

`npm run typecheck`, `npm run test:server`, `NEXT_PUBLIC_BASE_PATH=/kvant-next NEXT_PUBLIC_DEMO_MODE=true npm run build`. Серверные тесты проверяют валидацию, различие пропусков/нулей, парные вопросы, отсутствие исходного кода в записи, запрет перезаписи, авторизацию чтения и пагинацию. Реальная облачная база и центральный сбор требуют отдельного развёртывания по шагам выше.
