# Проектный навигатор

Цифровая образовательная среда сопровождения студенческих проектов: паспорт проекта, задачи и спринты, обратная связь куратора, апробация и упаковка результата в КОП.

## Запуск

```bash
npm install
npm run dev
```

Для локальной демонстрации без сервера можно задать `NEXT_PUBLIC_DEMO_MODE=true`. Тогда доступны только демонстрационные учётные записи `demo-team / demo` и `demo-curator / demo`. Не включайте этот режим в опубликованной версии.

## Серверная авторизация

Пароли команд и кураторов не должны находиться в клиентском коде. Cloud Function получает два обязательных секрета:

- `SESSION_SECRET` — случайная строка длиной не менее 32 символов;
- `AUTH_ACCOUNTS_JSON` — JSON-массив аккаунтов с хешами паролей.

Создайте новый секрет сессии:

```bash
openssl rand -base64 48
```

Создайте хеш каждого нового пароля, не сохраняя сам пароль в файле:

```bash
read -s AUTH_PASSWORD
printf '%s' "$AUTH_PASSWORD" | node cloud-function/hash-password.js
unset AUTH_PASSWORD
```

Используйте полученные строки в настройке `AUTH_ACCOUNTS_JSON` Cloud Function:

```json
[
  {
    "role": "student",
    "login": "team-01",
    "passwordHash": "scrypt$<salt>$<hash>",
    "track": "А1",
    "curatorLogin": "curator"
  },
  {
    "role": "curator",
    "login": "curator",
    "passwordHash": "scrypt$<salt>$<hash>",
    "name": "Имя куратора",
    "id": "c1"
  }
]
```

Также рекомендуется задать `ALLOWED_ORIGIN` равным адресу опубликованного приложения. Клиентскому приложению нужен `NEXT_PUBLIC_API_URL` с URL Cloud Function.

После входа сервер выдаёт подписанную сессию на 12 часов. Студентская сессия имеет доступ только к пространству своей команды и отправке её проекта. Просмотр всех заявок, изменение статусов и управление каталогом доступны только кураторской сессии.

> Ранее демонстрационные пароли находились в истории Git. Для апробации создайте совершенно новые пароли и не используйте старые значения повторно.

## Серверное хранилище

В YDB Document API необходимы таблицы со строковым или числовым первичным ключом `id`:

- `submitted_projects` — строковый `id`;
- `team_workspaces` — строковый `id`;
- `research_measurements` — строковый `id`, обезличенные измерения T0–T3;
- `approved_catalog` — числовой `id`.

Переменные подключения Cloud Function: `YDB_ENDPOINT`, `YDB_ACCESS_KEY_ID`, `YDB_SECRET_ACCESS_KEY`, `YDB_REGION`.

Перед началом T0 зафиксируйте формулировки восьми утверждений. Если инструмент изменяется после начала сбора данных, увеличьте `RESEARCH_INSTRUMENT_VERSION` в `cloud-function/index.js`, чтобы версии ответов не смешивались при анализе.
